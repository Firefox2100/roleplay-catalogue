# WorldSE 数据包

## 概述

角色扮演资源库中的世界（World）是为 **World Simulation Engine（WorldSE）** 设计的完整数据包。它们以 ZIP 压缩包形式上传，内含游戏数据 — 包括场景、角色、地图、脚本和世界配置 — 以及嵌入的图片。

世界作为独立的设定、模块或扩展包运行，角色可以在对话中与它们交互。每个世界都是独立资源库资源：拥有名称、描述、标签、可见性设置、语言、版本历史和导出 ZIP 文件。

## 使用方法

### 上传世界数据包

1. 在资源库中打开世界编辑器。
2. 点击**上传**并选择你的 `.zip` WorldSE 数据包文件。
3. 资源库会验证包结构并进行处理：
   - 嵌入的图片被提取并存储为**独立图片资源**。
   - 语言从世界的内部数据中自动检测。
   - 包元数据中的标签与你提供的附加标签进行合并。
4. 提供**名称**（必填，最多 200 个字符）和可选的**描述**（最多 10,000 个字符）。
5. 设置可见性、添加标签，如未自动检测则选择语言。
6. 提交上传。

### 设置封面图

1. 在世界编辑器中，打开**封面图**区域。
2. 使用**"选择封面图"**流程浏览从你的世界数据包中提取的图片（或任何其他已上传图片）。
3. 保存世界 — 封面现在指向所选图片。

上传 ZIP 中符合封面要求的图片会自动添加到你的图片库中。

### 导入标签数据

世界游戏数据元数据中的标签会通过合并方式与你通过资源库资源编辑器添加的标签**合并**。这样既保留了世界自带的分类，又让你能够添加自定义标签。你可以在已发布的世界页面上查看合并后的标签列表。

### 导出世界

1. 打开已发布的世界详情页。
2. 点击**导出**按钮。
3. 下载包含完整世界数据包（含所有嵌入图片）的 `.zip` 文件 — 与你上传的格式相同。

此 ZIP 可直接用于离线 WorldSE 客户端。

### 世界数据结构

已发布的世界包含以下数据：

- **世界配置** — 引擎设置、默认参数和全局选项。
- **场景** — 定义好的地点或舞台，角色可以在其中移动。
- **角色** — 世界中定义的 NPC 和实体。
- **地图** — 空间布局和位置参考数据。
- **脚本** — 由 WorldSE 引擎执行的自定义逻辑文件。

### 文件验证

每个已发布的世界都记录了 `artifact_file_name` 和 `artifact_sha256` 哈希。你可以使用这些值来验证下载的 ZIP 文件与已发布版本的一致性。

### Fork 世界

1. 打开任意已发布的世界。
2. 选择 **Fork**。
3. 资源库创建一个新世界资源。ZIP 文件由源数据构建，Fork 作者标注为上传者。
4. 引用图片的处理方式：
   - 如 Fork 作者名下已存在副本则**复用**（通过 SHA-256 哈希去重）。
   - 否则**复制**到 Fork 作者的存储中。
5. 独立编辑和重新发布 Fork 后的世界。

## 限制

| 限制项 | 上限 |
|--------|------|
| 最大包大小（`world_bundle_max_bytes`） | 100 MiB（104,857,600 字节） |
| 接受格式 | 含 WorldSE 数据的 ZIP 包 |
| 导出格式 | ZIP |
| 内容差异 | `null`（二进制 ZIP 格式无文本表示） |
| 支持语言 | 从世界数据检测（英文和简体中文） |
| 文件验证方式 | `artifact_sha256` |
| 资源类型过滤 | 可通过 `resourceType=world` 搜索 |

## 提示与注意事项

- **自包含导出。** 下载的 ZIP 数据包包含所有嵌入图片。无需连接资源库即可离线使用世界。
- **图片拥有独立身份。** 提取的图片是完整的资源库资源 — 你可以独立更改它们的名称、描述或标签，不受来源世界的影响。
- **标签可合并。** 世界数据标签和资源库标签合并后，你可以在资源库中添加额外的描述性标签，而不会丢失世界包自带的原有标签。
- **Fork 时自动去重。** 当 Fork 引用了资源库中已有图片的世界时，你的 Fork 会直接复用该图片。仅将尚未收录的图片进行复制，节省存储空间并加快下载速度。
- **哈希验证。** 始终将你下载的世界包的 `artifact_sha256` 与已发布哈希进行比对，确保文件在传输过程中未损坏。
- **二进制格式。** World 数据包使用二进制 ZIP 格式，因此所有已发布世界版本的 `content_diff` 均为 `null`。
