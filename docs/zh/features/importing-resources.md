# 导入资源

**导入**功能允许你将外部内容合并到已有资源的草稿中。导入是**创建后**操作 — 你必须先创建一个带有名称和基本元数据的资源，然后向其导入数据。

## 概览

导入处理以下两种场景：

- **合并**：资源已有草稿数据。导入的内容填充空白字段或追加到现有列表，保留已有的内容。
- **初始化**：资源尚无草稿数据。导入内容创建初始草稿。

### 合并策略

当导入到已有草稿时，系统使用**递归合并**算法：

| 数据类型 | 合并行为 |
|---|---|
| 字符串 | 保留现有值；导入值仅在当前值为空时填充 |
| 列表 | 拼接；去除重复项 |
| 字典 | 递归合并 — 保留现有键；添加新键 |
| 嵌套对象 | 在每一级递归合并 |

导入永远不会覆盖已有的非空内容。这意味着导入新卡片、lorebook 或预设时，你已有的编辑内容是安全的。

## 按类型导入

### 角色卡

**端点**：`POST /resources/{resourceId}/import-card`
**格式**：`.json`（V2 或 V3）或 `.png`（角色卡图片）

卡片导入端点：

1. 接受 **V2 或 V3** 格式的 SillyTavern 角色卡 JSON。V2 卡在导入过程中自动转换为 V3 格式。
2. 接受内嵌角色卡的 **PNG 图片**（系统读取 `tEXt` chunk — `ccv3` 对应 V3，`chara` 对应 V2）。
3. 将角色数据导入草稿。

在现有角色卡中导入时：

- **标签**：如果不存在则追加导入的标签（自动去重）。
- **描述**：保留现有描述；导入的描述仅在当前描述为空时填充。
- **封面图**：如果导入 PNG，该 PNG 文件成为资源的封面图（作为独立的图片资源存储）。
- **Lorebook**：如果 PNG/V3 JSON 包含内嵌 lorebook，则提取并合并到资源草稿中。

> [!TIP]
> **导入到已有卡片保留你的编辑。** 如果你已自定义过角色卡并收到了作者更新的版本，导入新卡以获得更新，同时保留你的修改。

### Lorebook

**端点**：`POST /resources/{resourceId}/import-lorebook`
**格式**：`.json`（V3 lorebook 或带内嵌 book 的卡片）或 `.png`（带内嵌 lorebook 的卡片 PNG）

Lorebook 导入端点：

1. 接受独立的 **V3** JSON 格式 lorebook（`lorebook_v3` 规范）。
2. 接受包含内嵌 lorebook 的**角色卡 JSON**（`chara_card_v2` 或 `chara_card_v3` 规范，`character_book` 字段）。
3. 接受包含 V3 lorebook 或带内嵌 lore 的角色卡的 **PNG**。

在现有 lorebook 草稿中导入时：

- Lorebook 条目按 `entryOrder` / `key` 标识符合并。
- 新条目追加；已有条目保留。
- 每个条目内的定义递归合并。

### 预设

**端点**：`POST /resources/{resourceId}/import-preset`
**格式**：`.json`（SillyTavern 预设）

预设导入端点：

1. 接受 **SillyTavern 预设 JSON** 文件。
2. 创建或替换草稿数据为预设参数。

由于预设是自我包含的参数集（模型设置、温度、上下文大小等），导入替换整个预设，而非逐字段合并。

### 数据包（世界）

**端点**：`POST /resources/{resourceId}/import-world`
**格式**：`.zip`（World Simulation Engine 包）

世界导入端点：

1. 接受包含世界数据、媒体和配置的 **WorldSE `.zip` 包**。
2. 提取包中的所有图片，在你账号下创建独立的**图片资源**，每个链接回数据包。
3. 将世界数据存储为草稿的 `worldData`。
4. 设置世界的封面图（如果数据包中指定了），来源为提取的媒体。

世界图片受益于 **S3 去重** — 如果图片的 SHA-256 已存在于你的账号下，则不创建新的副本。

导入后，世界资源的元数据更新如下：

- **语言**：从世界的区域设置推断。
- **标签**：从世界导入的标签追加到现有标签（应用去重）。
- **描述**：遵循合并规则 — 保留现有描述；导入的描述仅在当前描述为空时填充。

## 通过 UI 导入

每种资源类型在编辑页面都有一个导入按钮。点击导入，选择文件，然后选择一种支持的格式。系统验证文件、提取数据，并合并到草稿中。

## 约束条件

| 约束 | 限制 |
|---|---|
| 资源必须已存在 | 导入仅适用于已有资源（非创建时） |
| 文件大小 — 角色卡 | 受 `RC_IMAGE_MAX_BYTES` 限制（默认 20 MiB） |
| 文件大小 — 预设 | 受 `RC_PRESET_MAX_BYTES` 限制（默认 5 MiB） |
| 文件大小 — 数据包 | 受 `RC_WORLD_BUNDLE_MAX_BYTES` 限制（默认 100 MiB） |
| PNG 卡片检测 | 读取 `tEXt` chunks：`ccv3` → V3，`chara` → V2 |
| PNG 中 lorebook 提取 | 要求卡片的 `character_book` 字段存在 |

## 提示与注意事项

> [!NOTE]
> **导入更新时间戳。** 导入后，资源的 `updated_at` 字段刷新，将其置于日期排序列表的顶部。

> [!NOTE]
> **草稿与发布。** 导入仅修改**草稿** — 任何已有的已发布版本保持不变。你必须发布新版本才能将导入的更改释出给阅读者。

> [!TIP]
> **用导入完成清理。** 如果你在 SillyTavern 中有一个有 Bug 的角色卡，你可以创建一个空白资源并导入一个已知的正常 JSON 或 PNG 版本 — 系统将自动验证并转换格式。

> [!TIP]
> **PNG 导入自动捕获封面图。** 导入 `.png` 角色卡时，该图片文件存储为资源的封面图，因此无需单独上传缩略图。
