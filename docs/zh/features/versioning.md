# 版本管理与发布

角色扮演资源库对每一项资源（图片除外）采用**两级模型**：可编辑的草稿和一份或多份不可变的版本化发布。此设计允许你在迭代内容的同时，保留已发布修订的稳定历史记录。

## 概览

每一个角色、世界书、预设和世界资源由以下部分组成：

- **草稿（Draft）** — 随时间可编辑的内容数据。草稿拥有自己的元数据（名称、描述、标签、可见性），这些元数据可以独立于已发布的版本而变化。
- **版本（Release）** — 数据快照和元数据在特定时间点的冻结副本。版本是不可变的；一旦创建，其底层内容便无法更改。每个版本携带自己的可见性设置。

### 草稿与版本一览

| 方面 | 草稿 | 已发布版本 |
|---|---|---|
| 可编辑性 | 作者 / 协作者完全可编辑 | 数据不可变；发布时冻结 |
| 数据记录 | 存在于类型特定集合中，`resourceVersionId: null` | 存在于独立的记录中，`resourceVersionId` 设为版本 ID |
| 元数据 | 编辑时实时更新 | 发布时刻的快照 |
| 可见性 | 由 `Resource.metadata.visibility` 控制 | 独立可控；发布后仍可通过 PATCH 接口修改 |
| 创建者 | 编辑过程中的作者 / 协作者 | 仅作者（通过发布操作创建） |

## 版本化工作机制

### 创建草稿

通过 UI 或 API 创建资源时，系统会在相应类型特定的数据集合中创建一个空的草稿记录。该草稿立即可编辑；此时尚不存在任何版本。

### 发布版本

要发布版本，作者点击**发布**按钮（或调用发布接口）。发布过程中：

1. 当前草稿数据被**复制**（而非移动）到一个具有非空 `resourceVersionId` 的新不可变文档中。
2. 新建一个**版本记录**，版本号 `versionNumber` 从 `1` 开始递增。
3. 资源的**元数据在该时刻冻结** — 后续的草稿编辑不会回溯修改之前版本的元数据。
4. 对于角色卡，关联的世界书会**快照**到版本的 `linked_lorebooks` 字段中。如果某个 世界书是以草稿形式关联的，则捕获该 世界书的最新已发布版本。
5. 打包的**文件**（例如角色卡的 `.json` 或 `.png`，世界书/预设的 `.json`，世界的 `.zip`）上传至 S3 存储 `releases/{resource_id}/{version_id}{extension}`。
6. 文件的**内容差异**（基于 git 风格的统一差异格式）是相对于前一版本的渲染内容计算的 — 首版则与空文档比较，类似 git 首次提交。

### 更新草稿

发布后，**草稿仍可继续编辑**。你可以更改任何字段 — 文本内容、标签、描述、关联世界书、封面图 — 而不会影响之前的版本。这些更改在下次发布前累积。

### 管理版本可见性

每个版本都有自己独立的 `visibility` 字段：

- 发布时设置为 `PUBLIC`、`AUTHENTICATED` 或 `PRIVATE`（默认为草稿的可见性）。
- 发布后随时可以更改，无需重建该版本。

只有作者可以更新版本的可见性。

### 查看版本历史

从资源的详情页，你可以按 `versionNumber` **升序**查看所有已发布的版本。每个条目显示：

- 版本号和标签（例如 "1.0.0"）
- 发布时间
- 可见性（公开、已登录用户可见、私有）
- 文件大小和内容哈希
- 下载链接

点击某个版本可以查看其冻结的元数据和关联世界书引用。

## 约束条件

| 约束 | 限制 |
|---|---|
| 版本标签（显示文本） | 最大 100 字符，不可为空 |
| 可发布的资源类型 | 角色卡、世界书、预设、世界 |
| 图片资源版本 | 不支持单独发布（图片数据上传后即不可变） |
| 协作者 | 可以编辑草稿，但无法发布或删除版本 |
| 删除资源 | 仅支持删除没有任何已发布版本的资源 |

## 世界书快照机制

当你将 世界书链接到角色卡时：

- **以草稿形式链接**（`linkedLorebooks` 中 `versionId: null`）：角色卡在发布时始终引用该 世界书的最新已发布版本。如果该 世界书尚未发布过任何版本，则使用草稿本身。
- **以固定版本链接**（`versionId` 设为特定版本 ID）：角色卡锁定到该精确版本。这对于保留与特定 世界书修订版本的兼容性很有用。

每次发布时，系统会遍历链接的世界书并创建适当的快照。

## 提示与注意事项

> [!TIP]
> **版本标签面向用户。** 请使用语义化版本格式，如 `1.0.0`、`1.1.0` 或 `v2.3`，以便用户轻松识别最新版本。

> [!NOTE]
> 内容差异（`contentDiff`）存储已发布渲染文本的统一差异 — 角色卡内容**加上**合并的关联世界书内容。这让你可以以类似 `git log --diff` 的视觉方式浏览版本之间的变化。

> [!NOTE]
> **文件不可变，按 UUID 版本化。** S3 键 `releases/{resource_id}/{version_id}{extension}` 意味着即使后续版本覆盖了名称，你也可以始终重新下载特定版本。
